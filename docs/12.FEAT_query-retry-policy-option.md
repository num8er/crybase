# Query Retry Policy Option

## Description

Query retry policy option support adds a typed per-query `retry_policy:`
argument to `Query::Client#query` and `Query::Cluster#query`. The default is
`CryBase::CouchBase::RetryPolicy.no_retry`, and callers can pass an explicit
`CryBase::CouchBase::RetryPolicy` value for a specific Query call. The
canonical type is `CryBase::CouchBase::Policies::RetryPolicy`; the shorter
`CryBase::CouchBase::RetryPolicy` alias is available for normal use.

This feature only adds the public policy value and per-query API surface. It
does not add automatic retry execution, backoff, or retry error classification
behavior yet.

## Implementation

- Added `CryBase::CouchBase::Policies::RetryPolicy` with `max_attempts`,
  `delay`, `jitter`, `max_elapsed`, Query-error, and transport-error flags.
- Added `CryBase::CouchBase::RetryPolicy` as a short alias.
- Added `CryBase::CouchBase::RetryPolicy.no_retry` as the default per-query
  policy.
- Added `retry_policy:` keyword arguments to `Query::Client#query` and
  `Query::Cluster#query`.
- Forwarded `retry_policy:` through the existing `query(..., adhoc: false)`
  prepared-query path without changing retry behavior.
- Kept retry policy values out of the N1QL form payload so they are not sent as
  Couchbase Query options.
- Added `examples/query_retry_policy/example.cr` to show explicit retry policy
  values on client and cluster Query calls.
- Added specs for default policy values, explicit policy construction,
  validation, and per-query acceptance.
- Added pending executable specs for future policy-driven Query retry
  execution.
