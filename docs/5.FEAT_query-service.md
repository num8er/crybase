# Query Service

## Description

The Query service adds N1QL/SQL++ support through Couchbase's HTTP Query API. It posts statements to `/query/service`, supports positional and named parameters, readonly and scan-consistency options, TLS endpoints, JSON result parsing, and seed failover across multiple Query hosts.

## Implementation

- Added the `CryBase::CouchBase::Services::Query` namespace and public `CryBase::CouchBase::Query` alias.
- Added `Query::Client` for authenticated HTTP requests against the Query service.
- Added `Query::Cluster` for seed failover across multiple Query endpoints.
- Added `Query::Result`, `Query::Issue`, `Query::Error`, and `Query::ScanConsistency` for parsed responses, warnings/errors, raised query failures, and typed consistency values.
- Added `Query::Cursor` for single-use streaming row consumption through
  `query_cursor`.
- Added `Query::QueryContext` for bucket/scope Query context formatting.
- Added connection-string helpers for Query endpoints using `Service::Query` ports `8093` and `18093`.
- Reused `CryBase::Connectivity` for Query socket and TLS setup.
- Added unit specs with a local HTTP Query server, plus real Couchbase
  integration specs for readonly statements, seed failover, and seeded example
  user document queries.
- Added `examples/query_basics/example.cr` using shared example environment
  helpers, seeded `type = "User"` documents, bucket/scope query context,
  `query_as`, `query_each_as`, and `query_cursor`.
- Added `examples/query_cursor/example.cr` for streaming typed rows through
  `Query::Cursor#each_as`.
- Added `examples/query_mutations/example.cr` for raw SQL++ mutation statements,
  including `INSERT`, `UPDATE`, `DELETE`, `UPSERT`, and `SET ... FOR ... END`
  using Query context.
- Added shared typed row and Query context helpers to
  `examples/shared/structs.cr`, `examples/shared/structs/*.cr`, and
  `examples/shared/methods.cr`.
- Added `examples/shared/ulid.cr` for timestamp-based example document keys.
