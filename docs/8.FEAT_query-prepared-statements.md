# Query Prepared Statements

## Description

Query prepared statements add explicit prepare and execute-prepared APIs for repeated N1QL/SQL++ statements. `Query::Client` and `Query::Cluster` can also run `query(..., adhoc: false)` to prepare a statement once, cache the prepared plan name, execute by the `prepared` request parameter, and reprepare once when Couchbase reports that the prepared statement is missing.

## Implementation

- Added `Query::PreparedStatement` as the value returned by `prepare`.
- Added `Query::Client#prepare` and `Query::Client#execute_prepared`.
- Added `Query::Cluster#prepare` and `Query::Cluster#execute_prepared`.
- Added `adhoc: false` support to `query` on both client and cluster.
- Added client-level and cluster-level prepared statement caches keyed by statement text and generic Query options.
- Prepared statement cache keys include query context inputs.
- Added one automatic reprepare attempt when Couchbase returns Query error code `4040`.
- Added prepared request form generation with `prepared` and no `statement` field.
- Added unit and integration specs for preparing, executing, cache reuse,
  reprepare, and seeded example user document queries.
- Added `examples/query_prepared/example.cr` with seeded `type = "User"`
  documents, Query context, and typed result row iteration.
