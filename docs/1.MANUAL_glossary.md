# Glossary

This manual explains the Couchbase terms used by CryBase and maps them to the
current public API.

## Couchbase Data Model

| Couchbase | PostgreSQL comparison | CryBase status |
| --------- | --------------------- | -------------- |
| Bucket | Database-like container | KV selects this at connection setup and can switch it with `bucket=`; Query can read it from the URI path or use it as context. |
| Scope | Schema-like grouping inside a bucket | Query supports scope context; KV supports global scope defaults and scoped collection wrappers. |
| Collection | Table-like document set inside a scope | Query references collections in SQL++; KV targets them with `collection=`, `collection(...)`, or `scope(...).collection(...)`. |
| Document key | Primary-key-like lookup value | KV operations address documents by key. |
| Document value | JSON or binary document body | KV stores bytes or JSON-serializable values. |

For Query, bucket and scope can be context while collection stays in the SQL++:

```sql
SELECT META(u).id, u.name
FROM users AS u
```

With query context `commerce.ecommerce_shop`, `users` resolves to the
`users` collection in the `ecommerce_shop` scope of the `commerce` bucket.

For KV, the Couchbase path is bucket -> scope -> collection -> key. CryBase
selects the bucket during connection setup, can switch global defaults with
`kv.bucket = ...`, `kv.scope = ...`, and `kv.collection = ...`, and can build
explicit contexts with `kv.scope("scope").collection("collection")`.

## Services

| Service | Purpose | CryBase status |
| ------- | ------- | -------------- |
| Key Value (KV) | Direct document operations by key over the Couchbase binary protocol. | Implemented for bucket-level and scoped collection operations. |
| Query | N1QL/SQL++ over HTTP/HTTPS. | Implemented for statements, prepared plans, typed rows, cursors, context, topology, and seed failover. |
| Management | Cluster and bucket administration APIs. | Used internally for Query topology discovery; full client not implemented. |
| Search, Analytics, Index, Eventing, Views | Additional Couchbase services. | Modeled as services/endpoints, protocol clients not implemented. |

## Key Value Service

KV is the fastest path when the application already knows the document key.

Current KV support:

- `get`, `get_as`, `set`, `delete`, `touch`, get-and-touch.
- `increment` and `decrement`.
- Connection-level bucket/scope/collection defaults.
- Scoped collection wrappers through `scope(...).collection(...)` and
  current-scope `collection(...)`.
- TLS sockets.
- `KV::Pool` for a fixed-size pool of authenticated clients.
- `KV::Cluster` for seed failover.

Current KV limitations:

- No vbucket map routing yet; `KV::Cluster` is seed failover only.
- No CAS helpers, durability, observe, or automatic reconnect/retry execution.

## Query Service

Query is for N1QL/SQL++ statements, secondary indexes, projection, filtering,
joins, mutations, and ad hoc reads by criteria.

Current Query support:

- `Query::Client` for one Query endpoint.
- `Query::Cluster` for seed failover and topology discovery.
- `query`, `query_as`, `query_each`, `query_each_as`, and `query_cursor`.
- `prepare`, `execute_prepared`, and `adhoc: false` prepared-plan caching.
- Bucket/scope context through `query_context:`, per-call `bucket:`/`scope:`,
  chain wrappers, connection-level defaults, and Query connection string bucket
  paths.

## Retry Policy

`CryBase::CouchBase::RetryPolicy` is a value passed to Query calls:

```crystal
policy = CryBase::CouchBase::RetryPolicy.new(
  max_attempts: 3,
  delay: 50.milliseconds,
  jitter: 0.2,
  max_elapsed: 500.milliseconds,
)
```

`CryBase::CouchBase::RetryPolicy.no_retry` is the default. Retry policy values
are kept separate from N1QL form options so automatic retry behavior can evolve
without changing Query call sites.

## Scan Consistency

Scan consistency controls how fresh Query index reads must be.

```crystal
client.query(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u LIMIT 5",
  bucket: "commerce",
  scope: "ecommerce_shop",
  scan_consistency: CryBase::CouchBase::Query::ScanConsistency::RequestPlus,
)
```

Use stronger consistency only when the query must see very recent writes.

## Connection Strings

| Scheme | TLS | Notes |
| ------ | --- | ----- |
| `couchbase://` | no | Plaintext Couchbase services. |
| `couchbases://` | yes | TLS Couchbase services. |
| `http://` | no | Treated as a Management URL. |
| `https://` | yes | Treated as a Management URL. |

KV connection strings can include the bucket:

```text
couchbase://user:pass@node1/commerce
```

Query connection strings can also include the bucket as the default Query
bucket:

```text
couchbase://user:pass@node1,node2,node3/commerce
```

| Index | 9102 | 19102 |

## Public API Map

| Module / Type | Purpose |
| ------------- | ------- |
| `CryBase` | Top-level namespace and shard entry point. |
| `CryBase::Connectivity` | Shared plaintext TCP, TLS socket, and HTTP client construction helpers. |
| `CryBase::Connectivity::HostPort` | Strict parser/value object for `host:port` strings. |
| `CryBase::Connectivity::HTTPClient` | Shared HTTP client construction over Connectivity sockets. |
| `CryBase::Connectivity::SocketConfig` | Shared timeout and TLS socket options. |
| `CryBase::CouchBase` | Couchbase-specific namespace. |
| `CryBase::CouchBase::ConnectionString` | Parses supported connection string schemes and seed hosts. |
| `CryBase::CouchBase::Endpoint` | Value type for one Couchbase service endpoint. |
| `CryBase::CouchBase::Service` | Service enum with plaintext and TLS default ports. |
| `CryBase::CouchBase::Client` | Cluster endpoint enumerator and TCP probe client. |
| `CryBase::CouchBase::RetryPolicy` | Short alias for `Policies::RetryPolicy`. |
| `CryBase::CouchBase::KV` | Alias for `CryBase::CouchBase::Services::KV`. |
| `CryBase::CouchBase::Query` | Alias for `CryBase::CouchBase::Services::Query`. |
| `CryBase::CouchBase::Services::KV::Client` | Single authenticated KV connection. |
| `CryBase::CouchBase::Services::KV::Pool` | Fixed-size pool of authenticated KV clients. |
| `CryBase::CouchBase::Services::KV::Cluster` | Seed-failover KV client backed by one active pool. |
| `CryBase::CouchBase::Services::KV::ScopeContext` | Chainable KV scope wrapper. |
| `CryBase::CouchBase::Services::KV::CollectionContext` | Chainable KV scoped collection wrapper. |
| `CryBase::CouchBase::Services::Query::Client` | Authenticated N1QL/SQL++ Query endpoint client. |
| `CryBase::CouchBase::Services::Query::Cluster` | Query client over discovered topology with seed fallback. |
| `CryBase::CouchBase::Services::Query::Cursor` | Single-use streaming Query row cursor. |
| `CryBase::CouchBase::Services::Query::QueryContext` | Bucket/scope Query context formatter. |
| `CryBase::CouchBase::Services::Query::BucketContext` | Chainable Query bucket context wrapper. |
| `CryBase::CouchBase::Services::Query::ScopeContext` | Chainable Query bucket/scope context wrapper. |
| `CryBase::CouchBase::Services::Query::PreparedStatement` | Prepared Query statement name and metadata. |
| `CryBase::CouchBase::Services::Query::Result` | Parsed Query response rows, metadata, warnings, and errors. |
| `CryBase::CouchBase::Services::Query::Topology` | Parsed Query endpoints from Couchbase nodeServices payloads. |
| `CryBase::CouchBase::Services::Query::TopologyClient` | Authenticated Management API client for Query topology loading. |
