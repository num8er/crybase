# Query Reuse Context And Typed Rows

## Description

Query reuse, context, and typed rows make the Query service more practical for
application code. `Query::Client` now keeps a reusable HTTP connection, and
`Query::Cluster` keeps reusable endpoint clients across seed failover.
Callers can build bucket/scope query contexts without manually formatting
`query_context`, map result rows into `JSON::Serializable` types, or stream
rows through a block as they are parsed from the Query response.

## Implementation

- Added `Query::QueryContext` for Couchbase `query_context` values built from
  bucket and scope names with identifier escaping.
- Added `query_context:`, `bucket:`, `scope:`, and optional `namespace:`
  keyword arguments to Query statement, prepare, and prepared execution paths.
- Updated prepared statement cache keys to include query context inputs.
- Changed `Query::Client` to keep a reusable `HTTP::Client` and close it only
  on client close or transport reconnect.
- Changed `Query::Cluster` to cache one reusable `Query::Client` per endpoint
  and close cached clients on failover, topology replacement, or cluster close.
- Added `query_as(Type)`, `query_each`, and `query_each_as(Type)` to
  `Query::Client` and `Query::Cluster`.
- Added `Result#each_row` and `Result#each_row_as(Type)` helpers.
- Added unit coverage for connection reuse, query context formatting, typed
  row mapping, and streaming typed rows.
- Updated runnable Query examples to use Query context, `query_as`,
  `query_each_as`, and typed `Result` row iteration against seeded `User`
  documents.
- Updated README Query documentation with connection reuse, query context,
  typed row, streaming row, and raw SQL++ mutation examples.
