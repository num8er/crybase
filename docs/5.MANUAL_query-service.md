# Query Service

Use Query for N1QL/SQL++ statements, secondary indexes, filtering, projection,
mutations, typed rows, streaming rows, and prepared statements.

## One Query Endpoint

```crystal
require "crybase"

client = CryBase::CouchBase::Query::Client.from_string(
  "couchbase://Administrator:password@127.0.0.1/commerce",
)

client.scope = "ecommerce_shop"

result = client.query(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u LIMIT 5",
)

puts result.rows.first["name"].as_s
client.close
```

## Bucket And Scope Defaults

Use bucket/scope defaults when statements repeatedly target collections in the
same Couchbase scope:

```crystal
client.bucket = "commerce"
client.scope = "ecommerce_shop"

result = client.query(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u",
)
```

The collection stays in SQL++: `FROM users AS u`.
The `/commerce` path in `from_string` sets the same default bucket; use
`bucket =` when you build a client without a bucket path or need to change it.

## Chain Context

```crystal
shop = client.bucket("commerce").scope("ecommerce_shop")

result = shop.query(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u",
)
```

## Typed Rows

```crystal
struct UserRow
  include JSON::Serializable

  getter doc_key : String
  getter name : String
end

rows = client.query_as(
  UserRow,
  "SELECT META(u).id AS doc_key, u.name FROM users AS u",
)
```

## Streaming Cursor

```crystal
cursor = client.query_cursor(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u",
)

result = cursor.each_as(UserRow) do |row|
  puts row.name
end
```

## Prepared Statements

Use `adhoc: false` when the same statement shape is reused:

```crystal
result = client.query(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u WHERE u.active = $active LIMIT 10",
  named_args: {active: true},
  adhoc: false,
)
```

Prepare explicitly when the application needs to manage the prepared plan:

```crystal
prepared = client.prepare(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u WHERE u.active = $active LIMIT 10",
)

result = client.execute_prepared(
  prepared,
  named_args: {active: true},
)
```

## Query Cluster

Use `Query::Cluster` for Query seed failover and topology discovery:

```crystal
cluster = CryBase::CouchBase::Query::Cluster.from_string(
  "couchbase://Administrator:password@node1,node2,node3/commerce",
)

cluster.scope = "ecommerce_shop"

result = cluster.query(
  "SELECT META(u).id AS doc_key, u.name FROM users AS u",
)

puts result.rows.first["name"].as_s
cluster.close
```

The bucket path in the Query connection string becomes the default Query
bucket. Use `cluster.bucket = ...` and `cluster.scope = ...` for global
defaults, or `cluster.bucket(...).scope(...)` for one scoped context. Pass
`discover_topology: false` to keep static seed-only routing.
