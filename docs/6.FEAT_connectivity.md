# Connectivity

## Description

The Connectivity layer centralizes plaintext TCP and TLS socket construction for CryBase clients. Service implementations reuse it instead of creating `TCPSocket` or `OpenSSL::SSL::Socket::Client` directly.

## Implementation

- Added `CryBase::Connectivity` as the shared transport namespace.
- Added `CryBase::Connectivity::SocketConfig` for timeout, TLS mode, verification, hostname, and custom OpenSSL context options.
- Added `CryBase::Connectivity::HostPort.parse` for strict `host:port` parsing that returns a value object with `host` and `port`.
- Added `CryBase::Connectivity::TCPSocket` in `src/crybase/connectivity/tcp_socket.cr` for plaintext TCP socket creation and timeout setup.
- Added `CryBase::Connectivity::TCPSocket.open(host_port)` for `host:port` strings such as `127.0.0.1:12345`.
- Added `CryBase::Connectivity::TLSSocket` in `src/crybase/connectivity/tls_socket.cr` for TLS wrapping, hostname selection, verification mode, and custom context support.
- Added `CryBase::Connectivity::TLSSocket.open(host_port, config)` for TLS sockets from `host:port` strings such as `127.0.0.1:12345`.
- Added `CryBase::Connectivity.open_socket` as the service-facing helper that chooses plaintext or TLS sockets from a `SocketConfig`.
- Added `CryBase::Connectivity.open_socket(host_port, config)` as a proxy to `open_socket(host, port, config)` for service-facing `host:port` strings.
- Refactored the cluster probe, KV client, and Query client to reuse the shared connectivity helper.
- Added connectivity specs covering plaintext socket creation and TLS option compilation.
